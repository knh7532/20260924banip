## 잘된 점

- 테스트를 **골든값 대사 → 불변식 검증**으로 바꾼 것이 결정적이었다. "GPU당 1쿼리", "누적 라벨셋 ≤36", "In Queue가 실제로 발생" 같은 규칙은 값이 변해도 계속 성립해야 하는 것들이라, 동적 시뮬레이션에서도 회귀를 잡아낸다.
- 정적→동적 전환이 **계약(TV-C1)의 이름·라벨을 건드리지 않고** 끝났다(타입 1건만 v1.2로 개정). 덕분에 Grafana 대시보드는 상세 패널만 손보면 됐고, React 재구현도 같은 계약 위에서 진행할 수 있다.

## 어려웠던 점

- **신원 재사용이 조인을 깨뜨린다**는 걸 리뷰가 잡아냈다. `stmt_id`를 풀에서 재사용하면 `last_over_time`이 같은 ID의 과거 라벨셋을 되살려 many-to-many 오류가 난다 — 정적 데이터에서는 절대 드러나지 않는 결함이었다.
- 처음 기저값으로는 GPU 사용률이 100%에 붙어버렸다(부하 가산이 과했다). 30분 시뮬레이션으로 포화율을 재고 조정했다.
- 도착을 "빈 GPU에서만" 만들면 큐가 영원히 안 생긴다 — 대기열(In Queue) 상태가 화면에 있는데 데이터에는 없는 상태였다.

## 다음 phase에 반영할 개선점

- React판(R2~)은 처음부터 **instant vs range**를 구분해 설계한다(상태·신원은 instant, 집계는 range 창).
- 시뮬레이터에 "관측 가능한 상태가 실제로 관측되는가"를 확인하는 테스트를 표준으로 둔다(In Queue 사례).
