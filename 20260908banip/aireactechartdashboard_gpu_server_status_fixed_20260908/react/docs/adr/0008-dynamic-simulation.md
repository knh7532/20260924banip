# ADR-0008: 동적 시뮬레이션 — 쿼리 라이프사이클 + GPU 부하 결합

- 상태: Accepted
- 날짜: 2026-07-15

## 컨텍스트

1차(정적) 범위에서는 exporter가 원본 시안의 수치를 고정값으로 노출했다(DEF-1로 보류된 동적화). 정적 데이터에서는 시계열이 수평선, 타임라인이 단일 세그먼트로 나와 **화면의 시간축 요소를 검증할 수 없다**. 인간이 화면 조정을 마치고 동적화를 승인했다(2026-07-15).

또한 같은 데이터를 React 재구현(`../top_view_react`)이 소비하므로, 차트·브러시·구간 상세를 만들려면 값이 실제로 변해야 한다.

## 결정

exporter를 **동적 시뮬레이션**으로 전환한다.

- **도착 과정**: 노드별 포아송 도착(슬롯과 무관). 빈 GPU가 없으면 노드 큐에서 대기 → `sqm_query_state=2`(In Queue). 큐 상한 4/노드.
- **실행**: GPU 1장에 동시 1쿼리(타임라인 1행 1값). 지속은 로그정규(중앙값 75초, 30~180초로 절단) — **시간 압축**(인간 확정): 데모에서 세그먼트가 빨리 쌓이도록.
- **종료**: statement 메트릭 5종의 라벨셋을 `remove()`하고 실행 수 Counter를 올린다.
- **신원**: `stmt_id`/`query_id`/사용자를 **슬롯(GPU)에 고정된 3종**에서 재사용 — TSDB 누적 라벨셋을 12×3=36으로 상한(`remove()`는 TSDB 시계열을 지우지 않으므로).
- **GPU 지표**: 기저 사인파 + 랜덤워크 + 스파이크 **+ 실행 중 쿼리의 부하 가산**(유형별 강도). 기저값은 상한(100%)에 붙지 않도록 조정.
- **서버 카드**: 원본 시안의 고정 수치를 **포기**하고 서버별 성격(busy/normal/idle-burst)만 다르게 한다(인간 확정).
- **수집 일관성**: tick과 Prometheus scrape를 같은 락으로 직렬화한다(반쪽 상태 노출 방지).
- **계약 TV-C1 v1.2**: `sqm_query_executions_total`을 Gauge → **Counter**로 전환. 소비 측(Grafana)은 `increase(...[$__range])`로 마이그레이션.

## 대안

- **정적 유지**: 원본 수치와 정확히 일치하지만 시간축 요소를 검증할 수 없고 React 차트 개발이 불가능하다. 기각(인간 지시).
- **과거 데이터 백필(promtool)**: 켜자마자 화면이 차지만 구현·검증 비용이 크다. 기각 — 대신 시간 압축으로 5~10분이면 화면이 찬다.
- **stmt_id를 매 실행 새로 발급**: 현실적이지만 TSDB 누적 카디널리티가 무한히 증가한다. 슬롯 고정 재사용으로 기각.

## 결과

- 테스트가 **고정 골든값 대사 → 불변식 검증**으로 바뀐다(GPU당 1쿼리, 라벨셋 제거, 누적 상한, 범위, 재현성).
- 대시보드 상세 패널이 구간 집계에서 **현재 시점 selector**로 바뀐다(신원 재사용 시 `*_over_time`은 같은 `stmt_id`의 과거 라벨셋을 되살려 조인이 many-to-many로 깨진다).
- 기본 시간범위가 30분이 된다(시간 압축과 정합).
- 원본 시안의 서버 카드 수치(72%/986W 등)와 화면 값이 더 이상 일치하지 않는다 — 의도된 결정이다.
