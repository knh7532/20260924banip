# ADR R-0007: UX 10사이클 반영 — 표시 계층 결정 (Phase R9)

- 상태: Accepted (인간 확정 3건 포함, 2026-07-16)
- 날짜: 2026-07-17

## 컨텍스트

인간 지시로 실화면 4개 상태(All/단일 인스턴스/1366×768/공란)를 10개 렌즈로 순회
검토(10사이클)한 결과, R8 고정 그리드의 "내부 스크롤 모델"에 스크롤 어포던스가 없어
생긴 P0 잘림 2건과, C3가 기본 높이(320px)로 생성된 뒤 ResizeObserver가 축소하는
구조에서 오는 첫 프레임 y축 뭉개짐, 그리고 All 뷰에서 24슬롯 개별선이 4색 반복으로
식별 불가한 문제 등이 확인됐다. 데이터 계층(PromQL·계약 TV-C1 v2.0)은 문제가 없고
전부 **표시 계층**의 결정 사항이다.

## 결정

1. **C3 생성 시점 크기 고정 (`initialSize`)**: `MetricChart`/`Gauge`는 마운트 시
   컨테이너를 실측(`clientWidth/Height`)해 `c3.generate`의 `size`로 전달한다.
   320px 기본 생성 → RO 축소 경로를 제거해 첫 프레임부터 맞는 크기로 그린다
   (측정이 0이면 기존대로 RO에 맡긴다). RO 추적(`useChartResize`)은 유지.
2. **All 뷰 시계열 = 노드 평균 3선** (인간 확정): 인스턴스 미선택이면
   `gpuTimeseriesAvg`(`avg by(node)` 4종)를 조회하고 라벨 "GPU-Server-0N",
   신설 노드 팔레트 `--node-1/2/3`(GPU 4색·쿼리 6색과 불겹침)로 그린다.
   슬롯 상세(8선)는 서버 선택 시 본다 — 의도된 요약이며 세부 손실이 아니다.
   타임라인은 All에서도 슬롯 단위를 유지한다(행 단위 스캔이 목적이므로).
3. **MIG 쌍 구분 = M1 점선**: 색은 물리 GPU 공유(R-0006 유지)를 지키고, M1 라인에
   `stroke-dasharray`를 준다. 셀렉터는 `[class*="·M1"]` — c3 0.7.20의
   `generateTargetClass`는 공백만 치환하고 라벨을 보존하므로 "GPU-0·M1"/"S01·GPU0·M1"
   모두 잡히고, M0·노드 평균 라벨에는 "·M1"이 없어 오탐이 없다. 범례 스와치도 점선.
4. **내부 스크롤 어포던스**: R8의 고정 그리드·내부 스크롤 계약은 존중하되,
   `.timeline__plot-scroll`에 하단 sticky 페이드(잘림→"더 있음" 신호 전환)와
   내부 스크롤 영역 공통 웹킷 스크롤바(8px, thumb `--border`)를 준다.
   `.detail-col`은 `2fr/9fr` 고정 분할 → `auto minmax(0,1fr)`(시간 구간은 내용 높이,
   상세가 나머지)로 마지막 행 잘림을 없앤다.
5. **KPI 스트립** (인간 확정): canvas 최상단에 4타일(활성 MIG n/분모 · In Queue
   (>0 주황) · 총 처리행수/s · 평균 P95(활동 중 쿼리만)) — `kpi()` instant 5쿼리,
   `--dashboard-kpi-h` 64px. "이상 유무 3초 판단"이 목적. In Queue는 **환경 전체** 값
   (Codex 리뷰 반영): `sqm_query_state`의 계약 라벨에 위치(node/gpu/mig)가 없고 대기 중
   쿼리는 슬롯 미배정이라 필터·조인 모두 부정확 — 타일 라벨 "(환경 전체)"로 명시한다.
   같은 이유로 성능 테이블의 MIG 컬럼은 In Process(state 1) 행에만 값을 보이고
   대기·유휴 행은 "-"다(잔재 라벨 오표시 방지).
6. **상태 가시화**: `usePolling.lastSuccessAt` → 헤더 "갱신 HH:MM:SS"(끊겨도 보존 —
   정체 판단), 공란 골격(MetricChart "데이터 없음" 문구·ServerGauges NODES 자리표시
   카드), 첫 로드는 "불러오는 중…"으로 구분(`!disconnected && lastSuccessAt === null`).
7. **스파크라인 스택 — 시간축은 전력 카드 1곳** (R9.1, 인간 지시 "세로축이 작아서
   안 보여"): c3는 x축에 세로 30px를 예약해 카드당 y 플롯이 ~24px까지 줄었다.
   네 차트는 같은 x도메인 수직 스택이므로 위 3장(사용률·메모리·온도)은
   `axis.x.show:false`(예약 30→8px)로 숨기고 맨 아래(전력) 카드가 축을 대표한다 +
   `--dashboard-bottom-h` 384→432(16→18 rows). Grafana판(카드별 시간축)과의 의도적
   편차 — 근거는 판독성(공유 범례와 같은 사유). 툴팁은 4장 모두 시각을 표시한다.

## 결과

- 24슬롯 시계열의 시각 식별 문제가 구조적으로 해소되고, 공란·로딩·끊김 3상태가
  화면에서 구분된다. 테이블은 MIG 컬럼으로 Grafana판과 크로스뷰 일관성을 회복.
- 유지보수 주의: c3를 올리면 `generateTargetClass` 정규화가 바뀔 수 있다 —
  `[class*="·M1"]` 셀렉터와 R-0002(버전 고정)를 함께 봐야 한다.
- P3 백로그(plan.md R9): 경과시간 컬럼 · 리셋 버튼 위계 · 임계 초과 텍스트 보조 신호.
