# ADR R-0002: 차트는 C3 + D3, D3는 v5로 통일

- 상태: **Superseded by [R-0008](R-0008-echarts-unified-charts.md)** (2026-09-07 — 차트 엔진을 ECharts 하나로 통일, C3·D3 의존성 제거). 이전 상태: Amended (2026-07-17). 원문은 기록 보존.
- 날짜: 2026-07-15

## 개정 (2026-07-17)

빌드 툴체인이 vite 8로 올라가며 구버전 조합이 유지 불가능해졌고, 인간이
"신버전 유지·마이그레이션 완성"을 승인했다. 이에 v5 단일 핀 결정을 다음으로 대체한다:

- **앱 레벨 `d3@^7.9.0`** — D3를 직접 import하는 코드(타임라인)는 v7 API를 쓴다
  (`d3.event` 제거 → 리스너 첫 인자 event 수신).
- **C3 0.7.20은 자체 중첩 `d3@5.16.0`을 유지** — npm 중첩 설치로 두 인스턴스가 공존한다
  (`npm ls d3` → top-level 7.9.0 + `c3 > d3@5.16.0`). C3 렌더 코드는 top-level d3를
  import하지 않고, 타임라인은 C3의 중첩 d3를 import하지 않는다(상호 격리 규칙).
- 결과적으로 번들에 d3가 두 벌 포함된다(gzip 수십 KB 증가) — 정적 반출 특성상 수용.
- 동반 업그레이드: vite 5.4→8.1, vitest 2→4, TypeScript 5.5→5.9,
  `@vitejs/plugin-react` 5.2, `@testing-library/dom` peer 명시, `@types/d3` 7.4.3.
- AGENTS.md §0.1의 "v7 혼용 금지" 문구도 함께 개정되었다.

이하 원문(2026-07-15)은 개정 전 결정의 기록이다.

## 컨텍스트

인간 지시로 차트는 **C3.js와 D3.js**로 직접 그린다. C3 0.7.x는 D3를 peer/런타임 의존으로 요구하며 **D3 v5 계열에만 호환**된다(최신 D3 v7은 모듈 구조·API가 달라 C3가 동작하지 않는다). 한편 타임라인(간트)은 C3에 대응 차트 타입이 없어 D3로 직접 구현해야 한다.

## 결정

- **C3 0.7.20 + D3 5.16.0**을 정확 버전으로 핀한다. `npm ls`에서 D3가 **단일 인스턴스(deduped)** 로 해석됨을 확인했다.
- 역할 분담:
  - **C3**: 시계열 4종(GPU 사용률·메모리·온도·전력 — GPU별 라인), 서버 카드 게이지 12개(3서버 × 4지표, gauge 타입)
  - **D3(v5)**: 타임라인 간트 — GPU 행별 세그먼트, 드래그 브러시 구간 선택, 막대 클릭 필터
  - 테이블 2종은 차트 라이브러리 없이 React로 렌더
- D3 v7 등 메이저 업그레이드는 C3 호환을 깨므로 **금지**한다(AGENTS.md §4-8 이스케이프 대상).

## 대안

- **C3만 사용**: 간트/타임라인 표현 불가. 기각.
- **D3만 사용**: 라인·게이지까지 직접 구현해야 해 비용이 크고, 인간이 C3를 지시했다. 기각.
- **billboard.js(C3 포크, D3 v7 호환)**: 최신 D3를 쓸 수 있으나 지시된 라이브러리가 아니다. 기각(필요 시 재검토).

## 결과

- D3 API는 v5 기준으로 작성한다(`d3.event` 사용 등 v5 관용구 — v6+에서 제거된 API이므로 업그레이드 시 전면 수정 필요).
- C3는 SVG 기반이라 12개 게이지 + 4개 라인 차트가 동시에 뜬다. 폴링 갱신 시 **차트 재생성 대신 `load()`로 데이터만 교체**해 리렌더 비용을 억제한다.
- 번들 크기 증가(C3 + D3 v5 약 250KB gzip 이하 예상) — 정적 반출 시 문제되지 않는 수준.
